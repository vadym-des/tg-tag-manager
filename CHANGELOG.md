# Changelog — Telegram Tag Distribution Manager (TG Tag Manager PRO)

## [1.4.31] - 2026-11-11
### Fixed
- **Надійне автоматичне оновлення дати ігнорів заднім числом**:
  - Усунено конфлікт, коли збережений стан сесії `tg_session_state` фіксував стару дату і не давав їй оновитися наступного дня без жорсткого скидання сторінки.
  - Тепер система прив'язує дату сесії до поточної доби: щоранку при відкритті вкладки дата автоматично стає вчорашнім днем (сьогодні 11.11 ➔ ставиться 10.11; завтра 12.11 ➔ поставиться 11.11 тощо).
  - Якщо користувач власноруч змінює дату інпуту протягом дня, цей вибір зберігається до кінця поточної доби, а з новим днем — автоматично скидається до нового вчорашнього числа.

## [1.4.30] - 2026-11-04
### Added
- **Автоматичне збереження розподілу сесії**:
  - Введений текст розподілу в полі `inputIds`, значення калькулятора заявок та налаштування переносу тепер безперервно зберігаються в `localStorage` (`saveSessionState`).
  - При оновленні сторінки (Cmd+R / F5) або закритті та повторному відкритті вкладки **розподіл не зникає**, а автоматично відновлюється (`restoreSessionState`), захищаючи від випадкової втрати набраного списку операторів.
### Fixed
- **Динамічне авто-оновлення дати заднім числом**:
  - Дата ігнорів у полі «ІГ за [DD.MM] число» тепер автоматично перераховується на актуальний вчорашній день при настанні нової календарної доби, а також у реальному часі при поверненні користувача на вкладку (`visibilitychange` / `window focus`) без необхідності жорсткого перезавантаження сторінки (Cmd+Shift+R).

## [1.4.29] - 2026-11-03
### Added
- **Синхронізація за одним єдиним посиланням (All-in-One Cloud Key)**:
  - Повністю ліквідовано поділ на два складні блоки в модальному вікні хмари.
  - Тепер є **одне інтуїтивне поле**: користувач просто вставляє свій Web App URL (або посилання на Google Таблицю), натискає **«🔗 Підключити»** — і система миттєво підтягує актуальну базу, налаштовує щоденне авто-оновлення при відкритті сторінки та двосторонній авто-запис усіх змін назад у Google Sheets.
  - Додано прямий імпорт даних через JSONP з Web App (`importFromAppsScriptUrl`): лінк скрипта тепер самостійно віддає найсвіжіші дані без потреби вводити друге посилання на таблицю.
  - Додано кнопку **«Відключити»** для швидкого очищення хмарних посилань і повернення до локального режиму.

## [1.4.28] - 2026-11-03
### Fixed
- **Чесна діагностика стану Google Apps Script**:
  - Раніше через специфіку браузерного `mode: 'no-cors'` статус хмари міг помилково показувати `🟢 Хмара: ОК`, навіть якщо розгортання повертало `404 Not Found`.
  - Додано реальну перевірку живості Web App URL (`checkAppsScriptHealth`): якщо URL недоступний або розгортання не активовано, індикатор хмари показує червоний маркер `🔴 Хмара: Web App недоступний (404)`.
### Added
- **Оновлення коду Apps Script**:
  - Інтегровано підтримку JSONP-callback у `doGet(e)` та синхронізацію 5 колонок разом із полем «Графік» у модальному вікні налаштування хмари.

## [1.4.27] - 2026-11-02
### Fixed
- **Захист від затирання індивідуальних графіків операторів**:
  - При авто-підтягуванні даних з Google Sheets за посиланням (`cloud_auto_fetch`) додано механізм **розумного злиття (Smart Merge)**: якщо в Google Таблиці ще не додано колонку «Графік» або клітинка порожня, система автоматично зберігає вже внесені користувачем графіки з локальної бази замість затирання їх порожніми значеннями при оновленні сторінки (Cmd+Shift+R).
### Added
- **Оновлено інструкцію та код Google Apps Script**:
  - Додано 5-ту колонку `Графік` (`schedule`) у функції `doGet(e)` та `doPost(e)` шаблону Apps Script, що забезпечує збереження графіків прямо у Google Таблицю при двосторонній синхронізації.

## [1.4.25] - 2026-11-02
### Added
- **Індивідуальний графік роботи оператора**:
  - У модальне вікно «Редагування бази» (`#dbModal`) додано окрему колонку **«Графік»** (наприклад `до 16:00`, `9-16`, `до 4`, `до 4-ї`, `9-18` тощо).
  - Підтримка збереження графіка в локальній базі (`localStorage`), експорті в Excel (`.xlsx`) та хмарній синхронізації з Google Sheets.
- **Автоматичний контроль завершення зміни при розподілі**:
  - Якщо у оператора настав або минув час закінчення зміни згідно з його графіком, картка автоматично **знімається з вибору** (чекбокс вимикається), картка стає напівпрозорою та отримує бейдж `⏳ Зміна закінчилась (до HH:MM)`. Це захищає від випадкового нарахування заявок на оператора, чий робочий день закінчився.
  - Якщо до кінця зміни залишилося 45 хвилин або менше, на картці з'являється попереджувальний бейдж `⚠️ Скоро кінець зміни (до HH:MM)`.
  - У робочий час оператор показує інформаційний бейдж графіка `🕒 Графік: до HH:MM`.
### Fixed
- **Пріоритет додаткового виходу в дужках**:
  - Якщо оператор з індивідуальним графіком зазначений у тексті розподілу в дужках (наприклад `(53)` або `(73,32)`), він розпізнається як тимчасовий додатковий вихід (`⏱ Додатковий (до 11-12:00)`) і залишається активним для розподілу, не блокуючись основним графіком.

## [1.4.22] - 2026-11-02
### Added
- Повна підтримка хмарної синхронізації з Google Sheets (Варіант 1 та Варіант 2):
  - **Варіант 1 (Read-Only / Швидкий імпорт)**: пряме завантаження бази за посиланням на Google Таблицю через клієнтський Google Visualization API (JSONP) без бекенду, без CORS-блокувань та з можливістю авто-підтягування свіжих даних при кожному запуску сторінки.
  - **Варіант 2 (Two-Way Sync / Двостороння синхронізація)**: збереження будь-яких змін бази (додавання, зміна статусу або видалення оператора) безпосередньо у вашу Google Таблицю через Google Apps Script Web App.
  - **Інтерактивний статус-індикатор хмари**: стильний плаваючий бейдж із кольоровим маркером стану (🟢 Синхронізовано з фіксацією точного часу, 🟡 Збереження, 🔴 Помилка, ⚪️ Локальний режим).
  - **Модальне вікно налаштування хмари (`cloudModal`)**: вбудований готовий код Google Apps Script із можливістю копіювання в 1 клік та покрокова інструкція підключення.
- **Zero-Leak Policy**: усі персональні посилання зберігаються суто локально в браузері (`localStorage`), публічний код репозиторію залишається на 100% стерильним.
